How it follows a link

Before matching

Each short linkOnly links whose host, or a subdomain of it, is on the list.
  1. PwrRoute contacts the shortener. Every other link is matched without a request.
  2. It asks with HEAD, then GET if HEAD does not land.
  3. Each attempt follows up to 3 redirects and waits 750 ms at most.
  4. If it fails, the original link is routed, or the last redirect target seen.
  5. Activity and Test a link show the clicked link and where it went. Expansion itself logs and stores no URL; the optional Activity journal in Privacy is separate.

3Schema › rules.json options.urlShortenersProposal · for follow-up implementation

One optional key, three meanings, no merge. A list replaces the built-ins and never appends, which is why Custom list copies them in visibly (1b) rather than adding to them in secret.

3aThe three states, what Settings shows for each, and what rules.json holds.
Absent · Use built-in list
"options": { // no urlShorteners }

Inherits PwrRoute’s built-in hosts, including ones a later version adds.

[] · Off
"options": { "urlShorteners": [] }

No link is expanded and no shortener is contacted.

List · Custom list
"options": { "urlShorteners": ["go.example.com", "aka.ms", "bit.ly", …] }

Exactly these hosts. Built-in hosts are expanded only if they are in the list.

3bWho owns the effective list. Handler order does not matter: the only question is whether the Finicky config sets the key explicitly.

Validation, in the app and in the router. Each entry is a lowercase hostname: no scheme, path, port, space or wildcard; IDN hosts are stored in punycode and shown as typed. Duplicates are refused. A host matches itself and its subdomains, so go.example.com does not match example.com. A rules.json that fails validation keeps the last good snapshot, as for rules. Request limits are not settings: HEAD then GET, up to 3 redirects and 750 ms per attempt; on failure the original link or the last HTTP redirect target seen is routed. Privacy. Expansion writes no URL to any log or file. Activity and Test a link show the clicked link and destination as they already do; the optional Activity journal in Privacy is separate.
