1Rules · a new rule starts from the link you just opened

Add rule used to open a blank rail: an empty pattern with a problem under it, and nothing to say what you were trying to route. Now every new rule starts from the last link PwrRoute opened. The rail gains Start from, a picker over the recent links Activity holds in memory, with Clear to start blank. The pattern is the narrowest suggestion, selected so typing replaces it, and Try it holds the link. Nothing reaches rules.json until a browser is chosen, and the link itself never does.

1aRecommended. Add rule (or Add your first rule) on a fresh install, right after a link opened in Edge. The rail starts from that link: the pattern is git.example.com/acme/*, selected, with the wider git.example.com/* one click away. The title follows the pattern.

3Defaults by entry point

Every way to start a rule lands in the same rail. Start from shows only while the rule is a draft; a saved rule has its examples instead. “The last link” is the newest record Activity holds with a full URL. Clear drops the link, the pattern and Try it, and nothing else. An Overview card’s + Rule fills in no pattern: its browser is already set, so a pattern would make the rule whole and save it before the person chose it.
