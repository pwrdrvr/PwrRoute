1Update available · restart to update

Velopack checks GitHub Releases at startup and from Check for Updates, downloads in the background, and applies a downloaded update on the next launch (updater.rs). The catch is that PwrRoute is resident: it receives links all day and almost never relaunches, so "next launch" can be weeks away. The UI therefore has to offer Restart to update and keep offering it, quietly, until it is taken. A restart pauses routing for a couple of seconds, which the button says.

1aSettings › Updates with a downloaded update. The notes come from the release's CHANGELOG section. Later is not a snooze: the update stays downloaded and applies on whatever launch comes next.

2Becoming the default browser, per OS

One button in Settings › Browsers and in first run step 3, calling set_default_browser; three different OS answers (DefaultRequest). macOS shows a consent prompt (Prompted). Windows lets only the user choose, so PwrRoute opens Settings › Default apps on its own page (OpenedSettings). Linux sets it directly with xdg-settings, falling back to xdg-mime (Set). In every case PwrRoute then polls default_browser_status rather than assuming. OS-drawn surfaces are placeholders, not drawings.

2amacOS. The card waits while the prompt is up, then lands on one of two outcomes. A refusal is not an error: the button comes back, and nothing else nags.

Some desktops keep their own setting as well. If links still open elsewhere, check Settings › Default Applications in GNOME, or System Settings › Default Applications in KDE.

The strip's “default browser” chip (App Baseline 1a) reads the same status poll on every OS. When another app takes the default later, the chip turns to a warning and the button comes back; PwrRoute never re-registers itself. Velopack's install and update hooks on Windows only list PwrRoute as a browser (register_browser); they never call set_default_browser.
