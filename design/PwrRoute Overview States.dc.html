2Overview › A Finicky config in charge

With a Finicky config in charge, the map shows two sections in evaluation order, and the Everything else row names its owner. The new precedence setting is opt-in: "precedence": "pwrroute" in rules.json. It flips the handler order and hands Everything else to PwrRoute's default. A Finicky handler counts only when it actually matched, which is (Handler, Config) in the trace; browsers are never compared. Rewrites run config first either way. A config in charge is drawn in accent or neutral tones, never warning.

2aDefault mode. ~/.finicky.ts runs first and its defaultBrowser, Safari, takes everything else, so the ring and ribbon sit on Safari and its node carries the ∞. Orion isn't installed: its row and card are dashed and its route is the dashed not-running style, so the legend adds that swatch. The callout's button turns the override on right here.

Ranks count in evaluation order across both sections (01–08), so first match wins reads straight down. A row's tooltip names its own list, such as “handler 2 of ~/.finicky.ts” or “rule 1”. ƒ rows show what the function tests, by t1’s excerpt rule: a meaningful name and then its body in subtle text, or the body alone when the name is generic (match, url, …) or empty. With no source, “ƒ unnamed function” in muted text. The tooltip names the handler and shows the full source. Decided by JavaScript collects handlers whose browser is a function. A target the scan did not find is a dashed ghost card, and its rows get a dashed border, the same dashed badge, subtle name and “not installed” tag, and no count, because their links fall through to Everything else and are counted there. Their route is drawn in the dashed not-running style. Section headers are 24 high, 11/600 in sentence case (a file name must keep its case), with a 10.5 note on the right. The callout is radius 10 with padding 12/14 and a 28px icon tile.
The callout acts in place. Its button writes "precedence": "pwrroute" directly; it does not navigate. If describe() reports a toggle warning (Rules 5c), the warning shows as a line under the callout's detail before the click, with the same words. After the click the callout turns into the confirmation in 2b, with Undo where the button was (the in-place undo Rule Editing 4b chose over a toast). Undo stays until the user leaves Overview or edits something else; after that the callout settles to the plain one-line note “~/.finicky.ts's defaultBrowser, Safari, isn't used while PwrRoute's default takes everything else.” with Change in Rules ›.
Motion on toggle: the sections swap instantly. The ring fades out on Safari over 120ms and in on Chrome over 200ms. The Everything else route draws highlighted into the new owner’s node for 900ms, then settles to rest, with both ports lit. Undo plays the same hand-off back to Safari.

Callout copy, by how the two defaults compare. Each side is named as the map names a node, browser · profile, with the profile only when it names one. When both are the same browser, a side with no profile is “default profile”. Profiles are compared after canonical_profile, with same_profile.
(1) Different browsers (2a, 1e): “Your rules would run first, then ~/.finicky.ts’s handlers, and Google Chrome · Personal would take what is left instead of Safari.”
(2) Same browser, different profiles: “Your rules would run first, then ~/.finicky.ts’s handlers, and Microsoft Edge · Work would take what is left instead of Microsoft Edge · Personal.”
(3) Same browser and profile: “Your rules would run first, then ~/.finicky.ts’s handlers, and what is left would still open in Microsoft Edge · Work.”
After the click (2b) and once it settles, cases (1) and (2) name the config’s default the same way: “~/.finicky.ts’s defaultBrowser, Microsoft Edge · Personal, isn’t used while this is on.” Case (3) says “Your rules now run first. What is left still opens in Microsoft Edge · Work.”, and settles to “Your rules run first. What is left opens in Microsoft Edge · Work either way.”
