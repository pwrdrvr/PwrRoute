1Rules › Draft, Save and Discard

Supersedes Rule Editing 1a's “edits save on change” and 5's “every other edit still saves”. A click selects a rule; the rail edits it in place, but every change goes to a draft of that one rule. Nothing reaches rules.json until Save, and Discard puts back the saved rule. One rule is a draft at a time. Commands that act on a whole rule (the row menu's moves, Duplicate, Turn off, Delete with its tombstone, the header switch, Everything else) still apply at once, to the saved rule, and keep the draft.

⌘S · Ctrl+SSave the draft, from anywhere on Rules, also in a field. ReturnSave, in a Match, Open in, Profile, change or Rule set field. Return in Examples adds the example, in Name it names the destination, in Try it runs it, as before. EscCloses an open menu first, then collapses a field's selection, then discards the draft (with Undo). In the leave prompt (1d) it keeps editing. ⌘Z · Ctrl+ZUndo the last discard or delete, until the next edit.

The draft survives moving to Overview, Test a link or Activity and back; the rail's Rules item carries a dot while one is open, and everything else on those screens shows the saved rules, as the router routes. A draft whose rule another writer removed from the file comes back as a new rule on Save. Undo delete, Undo import and the agent and sync paths are unchanged: they go through the same store and the same check of the file.
