Order and density. Always last in its card, after “+N more profiles ▾” or “Show fewer ▴”. It never folds and doesn’t count toward the 4 nodes a routed card shows or the 2 an idle card shows, or toward “4 profiles · no rules yet”. The keyboard reaches it after the card’s profiles.
One per browser, not per profile. A private window keeps no history or cookies, so the profile it comes from is a detail of the rule, not a place of its own, and per-profile private nodes would double a busy card. A private rule’s route goes to the private node whatever profile it names. Its row target reads “Incognito”, or “Incognito · Work” when the rule names a profile, and the row tooltip adds “opens an Incognito window as Work”. The node tooltip reads “Google Chrome · Incognito: 2 rules, 14 links today · as Work, Personal”, naming the profiles only when some rule names one.
What feeds it. A rules.json rule with "private": true. A config handler whose fixed browser’s args carry a private flag (the engine’s is_private_flag; the Finicky API has no private field). Everything else, when the config’s fixed defaultBrowser carries one: its ∞ then sits on the private node. A private rule whose browser has no private mode opens a normal window (Note::PrivateUnsupported). Its route goes to the profile node, its row target adds a warn-text “not private” tag, and its tooltip says “Safari can’t open a private window from a link, so this opens a normal one.”
Copy. The idle tooltip is “No rules open an Incognito window yet” (“an InPrivate window”, “a private window”). Hovering an idle private node shows + Add a rule…, which opens Rules’ new-rule editor with that browser, no profile and private on (1g). The card meta counts private rules with the rest (“2 rules · 66 links today”). The header’s “3 in use” counts browsers, so it doesn’t change.
