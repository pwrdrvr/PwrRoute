1Don’t open, as a place a rule or Everything else can send links

A Finicky config could always say browser: null: the link is not opened anywhere. The visual rules could not, so the only way to keep unknown links out of a browser was JavaScript. Now Don’t open is the last lane in Open in, wherever a rule’s destination is picked, and a choice for Everything else. With Everything else on Don’t open, only links a rule chooses reach a browser; the rest are recorded in Activity, where each can be opened, opened somewhere else, or turned into a rule. rules.json writes it as the browser word "none" (a rule’s browser or the file’s defaultBrowser). The router already records a browser: null link as not opened; this canvas gives that state a face on every surface.

1aThe rule editor’s Open in. After the browsers comes one more lane, Don’t open: the not-opened badge (an em dash on a dashed tile, as the Overview’s Not opened card draws it), the name, the tag “kept in Activity” and one pill, Don’t open. Its border is dashed until it is chosen, so it never reads as a browser. Choosing it clears the rule’s profile and private window (they mean nothing here) and the Keep row stays. Under the lanes one line says where its links go: “Links this rule takes are not opened. Activity lists them under Not opened, where you can open one or add a rule.” No missing-browser or profile warning applies. Try it reads “This rule doesn’t open that link.” Right: the same rule on Rules, its target in secondary text with the badge.

2A link that was not opened, and opening it

A not-opened link is a decision waiting, so it must be easy to find and one step from opening. Activity gets a Not opened filter, each such row says who decided (a rule, Everything else, a config handler with browser: null, or Hold), and the expanded row leads with Open in…. Opening it never changes the rules; it dispatches the link once, to the destination picked, and the new row says it was opened from Activity. The same not-opened state serves Hold (the Hold canvas): only the reason differs.

2aActivity under All. A not-opened row’s Opened in reads Not opened beside the badge, in muted text. Its Rule chip names who decided as every row does (“rule 4”; “default” for Everything else on Don’t open, amber because no rule chose it; “cfg h 2” for a config’s browser: null; “held” for Hold). Took shows the resolve time. Not opened joins the filters after Everything else, with its count; it lists every not-opened row whatever the reason. A row opened later keeps its place and adds “opened later” to Opened in, with the browser it went to.

How it behaves.

rules.jsonA rule’s "browser": "none", or "defaultBrowser": "none", compared ignoring case. A profile or private flag beside it is ignored. The engine hands Finicky browser: null, so the result is the config API’s own not-opened browser and a config’s browser: null behaves the same. A word, not null: a JSON Merge Patch (an agent’s pwrroute_rules_apply) cannot set a field to null, and the Go host reads null as empty.
PrecedenceEverything else on Don’t open beside a Finicky config follows precedence as any default does: in the Go order the config’s defaultBrowser keeps everything else; with “Let PwrRoute’s default take everything else” on, unclaimed links are not opened. The config’s handlers still open what they claim.
Never a fallbackA not-opened link launches nothing, so the fallback browser never takes it. Don’t open as Everything else is not a browser to fall back to: when a chosen browser fails to open, or no config loads, the fallback browser takes the link, as with no default at all. The tray’s Pause routing target skips it the same way.
What is keptThe record, at its rule’s privacy level, like any dispatch. To open it later the router keeps the full link in memory while the record is kept (the retention count and hours); Open in… is offered only while it does, for a host-only record too (the link stays in memory, never in the record). A record read from the journal of an earlier run can’t be opened. Nothing more reaches disk than the journal already writes.
Opening itOpen in… dispatches the link once to the picked browser and profile, after the rewrites, as a click would; the new record names the record it came from. The rules are not changed and the not-opened record is not edited.
HoldHold records links without opening them, too: the same not-opened record, with “held” as who decided, the same filter, the same Open in….
Agentspwrroute_resolve says “not opened” and who decided. pwrroute_activity takes filter: "notOpened" and each not-opened entry carries a reason (rule, default, hold). pwrroute_rules_apply accepts "none" as a browser.
