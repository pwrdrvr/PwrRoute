1Send links: the menu bar dropdown

PwrRoute is the default browser, so the old trick of bringing the right browser window forward before a click no longer works. Send links lets the user say where the next click goes without writing a rule: Rules (normal), Next link (one by default, or a few; it counts down and goes back to the rules on its own) or All links (until switched back, or for an hour). The dropdown is where it lives, since the user is in another app when they want it. One click turns it on: the destination is already filled in (the last one chosen this session, else the Everything else browser). One click turns it off: Rules. The header chip says which mode is on.

1aRouting by rules, the default. The new section sits above Pause routing: a three-way switch and the destination it would use, shown before anything is on so the click is never a surprise. Click the destination row to choose another.

1bChoosing the destination. The row opens the same lanes the rule editor and Add a rule draw (Destination and App Pickers), compact: a lane per browser the scan found, its Default, each profile, then its private window in the browser’s own word, dashed with the mask. Hidden browsers and PwrRoute are left out; a browser with no private window from a link has no such pill. The destination’s pill is lit, its lane ringed. One click on a pill is the whole choice and closes the list; if a mode is on, the new destination applies from the next link. The list scrolls past about four lanes.

3How it behaves

The decisions behind turns 1 and 2, for whoever builds it.

3aBehaviour
Where it appliesIn the router, after the rules ran, exactly where a pause applies: rewrites still run, the record keeps the privacy level its rule gave it, and the destination replaces whatever browser the rules chose, a browser: null handler included. Test a link and Try it ignore it; they say what the rules would do. Which links countEvery link the router dispatches: clicks the OS hands over, links forwarded by a second launch, links from Help and from an agent’s pwrroute_open. One count per link, taken on the dispatch thread, so two links arriving together never both take the last one. A link the router refuses (not a URL) does not count. Next link1 to 99 links, then back to Rules on its own. The count lives in the router; the tray and the window read it after every dispatch. All linksUntil switched back, or for 1 hour. An hour that runs out goes back to Rules on its own, and the surfaces follow within a second. DestinationA browser, a profile (or the browser’s own), or its private window, picked from the lanes every destination picker in PwrRoute draws; a destination the scan no longer finds keeps a lane of its own, first, marked not installed. The first one offered is the last chosen this session, else the Everything else browser. Changing it while a mode is on applies from the next link and keeps the count. PauseStays its own control and shares the router’s one slot: pausing ends a send, sending ends a pause, Rules ends both. It keeps its warning tone and its “paused” records; a send is accent, because the user chose it. Private windowA link sent to a private window is kept at most host-only, as a private rule’s link is. RestartMemory only. Quitting PwrRoute, or a restart for an update, goes back to Rules. A send is for the next few minutes of work, not a setting. Hero orderConfig didn’t load, then paused, then sending, then not the default browser, then can’t tell, then routing. The strip chip and rail foot follow the same order. WordsChip and foot: “next link · {browser}”, “all links · {browser}”. Tray chip: “next link”, “all links”. Activity tag: “next link”, “all links”. Trace and tray recents: “next link 1 of 3 · skipped rule 2”, “all links · skipped config handler 4”. Tooltip: “PwrRoute · next link · Microsoft Edge · Work”. Not yetAn MCP tool (“open my next click in X”) would need its own permission in the role matrix; left for a later change.
