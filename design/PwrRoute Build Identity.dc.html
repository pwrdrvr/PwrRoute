1Main window › which build is this?

A dev build can be any of a dozen worktrees on any branch, and the window never says which. The rail’s foot gains a build block under the routing line: the checkout, the branch and the commit, each one click to copy its full value (the whole path, the whole branch, all 40 characters of the SHA), and a copy button that takes the three lines together. The commit is always shown, so a detached HEAD still says exactly what it is. Everything is captured when the binary is built; the app never reads a checkout at run time.

1aA dev build from a worktree on a branch, nothing uncommitted. “Dev build” in the warning tone with the version and profile. The checkout shows as its last two folders (a worktree’s id is the part that tells them apart); the commit as 8 characters and its subject, cut with an ellipsis.

Where links go

What is a dev build. Anything that is not a release: a build whose HEAD is not exactly the tag v{version}, or that had uncommitted changes, or that was built in the debug profile. A CI preview build is a dev build too; it shows branch and commit but no checkout (its path is the runner’s). Rows. Mono 10.5 on 20px rows, glyph 11px --text-subtle, value --text-secondary; the row is the copy target, padded 6px into the rail’s gutter so the hover fill does not touch the text. Hover: --bg-panel-hover fill, --text-primary, the copy glyph at the right. Copied: the glyph becomes a check in --success-text and “Copied” replaces the ellipsis for 1.5 s. Header. “Dev build” 9.5/600 tracked in --warn-text, then the version and profile in mono --text-subtle, then a 20px icon button. Checkout. ~ for home; past the rail’s width, the last two folders. Tooltip. The app’s usual one: “Click to copy …”, then the full value in mono, and for the commit its subject and date and, with changes, when it was built. A detached HEAD’s branch row copies nothing; its tooltip says the commit names it. Never at run time. The values come from git when the binary is built; nothing reads the checkout while the app runs.

2Settings › About › This copy

About’s “This copy” card spells the build out in full, with Copy build info in the card’s header (the same text the rail’s copy button writes). Each value sits in the Settings window’s command box with its own Copy, as Local agents does with its commands. Diagnostics’ version line gains the short commit, and its Copy carries the same lines.

2aA dev build with uncommitted changes. Version keeps its two lines; Source is new: the checkout’s full path, the branch, the full commit with its subject and date, and a warning line for the changes with the build time.
