Why two patterns, not a new one. Finicky’s * matches any run of characters and a pattern that starts with it gets no scheme, so *.example.com/* needs a dot before example and never matches https://example.com/; *example.com/* would, but also matches notexample.com. A rules.json rule’s match is already a string or a list, which the Go host and Finicky read as “any of these”, so the domain choice is the list ["example.com/*", "*.example.com/*"]: the importer’s existing form, readable by every older build, no new syntax.
