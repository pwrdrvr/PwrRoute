1Settings sections

“Configuration” named everything, so the sections say what they hold. Configuration becomes Config Files, Sync becomes Cloud Sync, and Short Links leaves Config Files for a section of its own. The nav takes PwrAgent’s Settings shape (its AI Providers group): group labels, and a caret with one child row per thing for the two sections that own several (cloud folders, config files), each with a status dot and an OFF or NOT USED chip. About still leads; Browsers still opens first.

1aThe nav groups its sections the way PwrAgent’s Settings does: small group labels, and a section that owns several things gets the directory caret and one row per thing under it, on a guide rail. Cloud Sync lists every cloud folder it found or was given: a green dot syncs, a dim dot with OFF is found but not added, amber is unavailable or waiting, red a conflict (the old .xdot moves onto the folder that has it). A click on a child opens Cloud Sync and brings that folder’s row into view, marked with the accent rail; the child row lights the same way. Groups start open; the caret folds one for the session.

2The Finicky config across machines

rules.json alone is half the routing on a Mac where a Finicky config runs first. So Also sync is on by default while a config is in charge, and the folder’s sync.json records, with each rules.json it saves, the config it ran after (runsAfter, its shown path). Another Mac reads that and says what is missing, instead of quietly routing differently.

2aA Mac with no Finicky config joins a folder whose rules.json was saved on a Mac where it runs after a config, and that config is in the folder. Nothing changes on its own: the row says what is missing and offers Use it on this Mac, which writes it to ~/.finicky.js (never over a file that is there), puts it in charge, and turns on Also sync so it keeps up. Until then the folder’s child row in the nav is amber.
