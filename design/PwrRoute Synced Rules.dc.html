1Settings › Sync

Rules sync through a folder the person already syncs (iCloud Drive, Google Drive, Dropbox, or any folder), never through a PwrRoute server. For each one PwrRoute keeps <folder>/PwrRoute/ with rules.json, a sync.json manifest written last, and finicky.ts when that is on. A new Sync item joins the Settings nav between Configuration and Privacy. The pane has four cards: What syncs (the disclosure), Sync to (the folders, one row each), What goes in the folder (rules.json and the optional Finicky config) and This machine (its name, and in turn 2 what the shared names mean here). In the UI a synced place is a folder; destination is kept for the named targets rules open links in. Turns 2 to 4 (what the names mean on each machine, sync status in the window and menu bar, Linux and Windows) are in PwrRoute Synced Rules Machine.

1aNothing set up. The disclosure comes first and is the only thing in the pane before a folder is added: what is copied, including the example and test URLs, and who can read it. Sync to lists the folders PwrRoute found by exact path (Google Drive by listing ~/Library/CloudStorage once, when the pane opens), each with Add, and Choose a folder… for anything else. The path shown is the one PwrRoute will use.

How a check runs, per folder and per file: PwrRoute compares this Mac’s file and the folder’s against the hash they last agreed on. Only the folder changed: it pulls, backing this Mac’s up first. Only this Mac changed: it pushes. Both changed: Conflict, nothing written. A pull counts as a local change, so the next check pushes it to the other folders. Checks run every minute, on window focus, after waking, after every save (the Rules screen, first run, Settings and agents) and on Sync now. Backups live in <data folder>/sync/backups; the newest 20 are kept. macOS prompts only follow a click on Add or Sync now.
