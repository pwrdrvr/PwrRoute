1Incoming links: one control for what the next links do

The user asked for two things: a better way than the tray’s Send links switch and Pause toggle to change what the next link does, and the same control at the top of the Overview, which never had one. And one new thing: Hold, which records links and opens none, for the next link, the next few, or a while, so the user can see a link before it opens, for instance to write a rule for a link the sending app never let them inspect. This canvas supersedes Send Links turn 1 and the tray’s Pause row; Send Links’ window turn (the node’s Next link here, the destination pill) stands.

1aOne question, four answers. Rules is normal. Send takes links to a browser the user picks. Hold records links and opens none, so the user can see them first. Pause sends every link to the Everything else browser. Send and Hold say how many: the next link, the next few, for a while, or until switched back. Pause has no scope: it is the escape hatch for misbehaving rules and lasts until resumed.

1bWhy it replaces Send links (Send Links 1a): that switch mixed how many (Next link, All links) with an unspoken what (send), kept Pause apart as a second control that did the same kind of thing, and had no room for a third action. Now the switch says what; one For row says how many or how long; one live line says what is on, counts it down and ends it in one click.
Turn it onOne click on Send, Hold or Pause. Send uses the destination shown (the last chosen this session, else the Everything else browser); Send and Hold use the scope shown (the last chosen this session, else the next link). Nothing else to confirm.See it is onThe segment lights in the mode’s tone; a live line under the controls says what happens and what is left: 2 of 3 left, 41:52 left, until you go back to rules. The tray chip, strip chip, rail foot and Overview hero say the same.Turn it offOne click: the live line’s Back to rules (Resume when paused), or the Rules segment. A count or a time that runs out goes back to Rules on its own.Change it while onThe For row and the destination apply from the next link. Changing the count keeps what was used: 1 of 3 used, set to 5, reads 4 of 5 left. Changing the time restarts it from now.TonesRules neutral; Send accent, as before; Hold info blue (the user chose it, nothing is wrong, links are waiting); Pause warning, as before.

4Held links in Activity

Activity is where a held link lives and where it can always be opened from, whatever the tray shows.

4aActivity on Not opened, the filter the Not opened canvas adds (2a): held links are there with every link a Don’t open rule chose. A held link’s Rule chip says held 2 of 3 in info blue; Opened in is the shared — Not opened. Unlike a Don’t open link, a held link has a rules’ answer, so it leads with it. Expanded, it shows the whole URL first, then what the rules would do, then the actions: Open in Google Chrome · Work (primary, the rules’ answer), Open in…, Add a rule…, Copy link. A link whose rule keeps only its host still opens in full: the whole link waits in memory until it is opened or leaves Activity.

5How it behaves

The decisions behind turns 1 to 4, for whoever builds it.

5aBehaviour
Where it appliesIn the router, after the rules ran, in the one slot Send and Pause already share: rewrites still run and the record keeps its rule’s privacy level. Hold records the link with where the rules would have opened it and opens nothing. Test a link ignores all three.Which links countAs Send Links 3a: every link the router dispatches (clicks, forwarded links, Help, an agent’s pwrroute_open), one count each on the dispatch thread. Opening a held link is not held again and does not count.One state, two causesA held link and a link a “Don’t open” rule or default chose are the same thing to the router: recorded, not opened, waiting. The trace says why (hold, rule or default); Activity, the tray and the MCP tools show and open both the same way.How long a held link waitsAs long as Activity keeps it: the same count and age as Settings › Privacy, cleared by Clear. With nothing kept, nothing can wait, so Hold is unavailable and its segment says why. A link whose rule keeps nothing (counted only) cannot be opened later.OpenOpen sends a held link where the rules send it now; Open in… where the user picks; both as a new dispatch with the link’s app, so a rule made from it still offers “Any link from <app>”. Open all opens every held link, oldest first.RestartMemory only, as before. Quitting or restarting for an update goes back to Rules and forgets held links; with the journal on, their records remain, but not to open. While links are held the tray’s Quit row says “2 held links will be lost”.Scope limitsLinks 1–99. Time steps 15, 30 min, 1, 2, 4, 8 hours. Until off has no limit. The last scope and destination are remembered for the session.Hero orderConfig didn’t load, then paused, then holding, then sending, then not the default browser, then can’t tell, then routing.WordsTray chip: “next link”, “next 3”, “sending”, “holding”, “paused”. Strip chip and rail foot: “holding · 1 of 3 left”, “sending · Microsoft Edge”. Activity chip: “held 1 of 3”, “held”, then “opened” on the row that opened it. Opened in: “Not opened”, “opened later in Google Chrome”, as the Not opened canvas words them.Agentspwrroute_activity takes filter: "held" (a subset of "notOpened"), gives each not-opened entry its reason and whether it can still be opened, and reports the hold in force; nothing lets an agent turn Hold on or open a held link without a new permission in the role matrix.
