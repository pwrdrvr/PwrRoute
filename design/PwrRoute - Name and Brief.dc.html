1The name: PwrRoute

A fourth PwrSuite app, next to PwrSnap, PwrGit and PwrAgnt. The job is routing: every link that hits the OS default browser is rewritten and sent to the browser (and profile) the rules say. Four candidates were drawn in the family wordmark; PwrRoute is the pick because it names the mechanism, reads as infrastructure, and its domain is unregistered. PwrLink was dropped first: pwrlink.com already has nameservers. Finicky is credited, not cloned: inspired by Finicky, tested for compatibility with Finicky configs.

2Brief, assumptions and the window map

What the rough cut in the finicky worktree already decided, what this design assumes on top of it, and where each surface lives. The other three files in this project draw the surfaces: PwrRoute App Baseline (rules, test, activity), PwrRoute Settings (browsers, configuration, local agents) and PwrRoute Tray and First Run.

2aAssumptions this design is built on. Each one is cheap to reverse now.

Carried from the rough cut

  • A resident Go router owns URL dispatch and keeps working with the Electron window closed. Electron is the settings and diagnostics app, as in the apps/pwrfinicky rough cut.
  • Visual rules live in rules.json under the platform config directory. A Finicky .js/.ts config is used only when selected, runs first, and owns the default browser while active.
  • Full URLs stay in memory; disk logs carry timings, never URL contents. The Activity view says so in place.
  • Default-browser registration is an explicit action. Nothing changes the OS default at launch.

Decided here

  • JSON for visual rules, JS/TS for power. Finicky's move to JSON is adopted for what a UI can edit (wildcard and regex matchers, browser and profile, static rewrites). Function matchers and URL transformers stay JS/TS, surfaced as fn chips, never silently dropped.
  • Rewrites and handlers are two lists, as in Finicky v4: every matching rewrite runs in order, then the first matching handler wins, then the default. The UI keeps that order visible instead of merging them.
  • Trace, not just result. Test a link shows each step that fired. The same trace is what Activity expands and what the MCP tool returns.
  • Opener-aware rules match on the sending app (name or bundle id). Window title is drawn as unavailable on the first host, matching the README.
  • MCP over loopback with OAuth, the PwrSnap/PwrGit door: Settings › Local agents, roles, sessions, Revoke. Port is a placeholder; PwrSnap holds 51729.
  • Family chrome: 40px strip, stoplights at (16, 13), brand at x=96, 20px mark, 17px wordmark with the app half in --accent. Settings is its own window, as in PwrSnap and PwrGit.
