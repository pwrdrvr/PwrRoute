# Changelog

## Unreleased

- Overview - The window now opens on Overview: whether links are routing (or paused, not reaching PwrRoute, or held up by a config that did not load or reload), a setup card for what is left, today's links, Everything else, rewrites and failures, and a map of every rule in the order it runs with a curve to the browser and profile it opens. Hovering a row or a card lights its routes, a click pins them, and rows open their rule in Rules. Rules opens as a list with nothing selected.
- Who takes everything else - With a Finicky config in charge, `rules.json` can say `"precedence": "pwrroute"`: its rules run before the config's handlers and its `defaultBrowser` takes every link nothing claims, in place of the config's (fixed, `null` or a function). Left out, the order is Finicky's as before. The Rules banner's switch, Overview's callout (with Undo), first run and Settings › Configuration › Everything else all write it, say what changes (a `defaultBrowser` function that stops running, a handler that matches every link, no default of PwrRoute's own) and, when the file cannot be written, leave the choice where the router has it and say why. `pwrroute_rules_apply` refuses a `precedence` other than `"pwrroute"` or `"config"`.
- Who routed a link - Activity, the tray's recents, Test a link, Try it and MCP traces name the rule that routed a link by its list and number ("rule 3" for `rules.json`, "config handler 2" for the config) and a default by its owner ("PwrRoute's default", "~/.finicky.ts's default"). Activity's Unrouted filter is now Everything else, and the Rules list counts today's links per rule.
- A config that does not load - When the Finicky config has never loaded (broken at launch, or broken when it first appears), PwrRoute leaves it out and routes with `rules.json` alone: your visual rules and rewrites keep running and PwrRoute's default takes everything else until the config loads, where before every link went to the fallback browser. A config that loaded once and then fails a reload still keeps routing with its last good version. Overview, the Rules banner, first run and Settings say which of the two it is.
- First run - With a Finicky config the steps are the config (keep it, import its rules or stop using it), Everything else (preselected from the config's default, the OS default or the first browser found, with who owns it while the config runs) and the default browser. Import N rules shows Importing… until the importer answers, Don't use it turns the config off, a choice that cannot be saved says why, and finished steps fold under Where links go.

## v0.1.0-rc.3 - 2026-10-22

- Window placement - New windows open on the display you are working on instead of the primary one: the main window from the tray (Open, Test a link, Rules, Activity), the Dock or the app menu, Settings, the importer, first run and an agent's approval window open on the display of PwrRoute's focused window, else the one under the pointer. A window that is already open stays where it is.
- Popovers and menus - The tray dropdown is as tall as what it shows, with no empty band below Quit, and grows or shrinks with it while open (keeping its top under the menu bar); on a display too short for it, the middle scrolls. Its pause line, tooltip and recents name a browser `rules.json` gives by bundle id ("Microsoft Edge", not `com.microsoft.edgemac`), as does Activity's Opened in. Select lists (Activity's Add a rule browser and profile, Test a link's app, first run's browser and profile, the agents' role) are at least as wide as their field and scroll past 8½ rows; a browser with three or more profiles shows a count instead of every name, and long names, profiles and the row menu's Save hint end in an ellipsis instead of running past the edge.
- Add a rule - With a Finicky config in charge, a rule added from Activity now shows on the Rules screen: the visual rules open with the new handler selected, and the row's menu offers Show handler N in Rules. Add checks the rule before writing it: a rule `rules.json` already has is not added again, and one that would never take its link (an earlier rule, or a config handler, takes it first, or the pattern misses) keeps the sheet open and says which; a second click adds it anyway.

## v0.1.0-rc.2 - 2026-10-22

- Browser hand-off - A profile, private-window or argument link for a Chromium browser that is already running opens without focus bouncing between apps. The short-lived instance `open -n` starts for the hand-off now starts in the background (`open -g`), and the running browser brings its own window forward. A browser that is not running still comes forward as before; Firefox is unchanged.
- App icon - On macOS 26 the app icon fills its squircle like other apps' instead of sitting shrunk on a light plate: the bundle ships an Icon Composer icon compiled into `Assets.car` (with a derived `Icon.icns` for older macOS) in place of a bare `.icns`.
- DMG - The macOS DMG opens to a window laid out like PwrSnap's, PwrAgnt's and PwrGit's: the PwrRoute wordmark, the app and an arrow to Applications on a branded background, the app icon as the volume icon, and a volume named `PwrRoute <version>-universal`.
- First run - Step 1 offers a profile for a browser that has them (Chrome, Firefox and the like) and saves it as `rules.json`'s `defaultProfile` beside `defaultBrowser`. Step 3 flips to done as soon as macOS reports PwrRoute as the default: the window re-reads the answer every second while it is open, and coming back to the window right after the dialog no longer counts as a refusal while LaunchServices catches up. A default browser PwrRoute's catalog does not list is named by its app ("PwrFinicky"), not its bundle id. The main window opens on the display the first-run window was on.
- Finicky importer - Import to visual rules…, first run's Import N rules, Settings › Configuration's Review import… and File › Import Finicky Config… open the importer: Review shows each rule's source lines and verdict (imports exactly, stays JS, or a suggested pattern the config's own function agreed with on every probe link), Place puts the imported handlers before, after or instead of yours, and Choose source keeps the config in charge or switches to visual rules (importing a file that is not in charge never puts it in charge or turns the one in charge off unasked); rules.json is written once, with Undo import, and the config is never changed.

## v0.1.0-rc.1 - 2026-10-21

- Rules - A `rules.json` rule or `defaultBrowser` that names a browser by bundle id or `.app` path now launches it when a profile is set (the handler carries Finicky's `appType`), macOS `open` starts a new instance whenever a config's `args` are passed so a running browser receives them, and a `~/` path expands to the home directory.
- Resident lifecycle - A downloaded update no longer applies at launch (a launch is usually for a link); it installs when PwrRoute quits, from the app menu or the tray, or from Restart to update. Checks run every 6 hours while running. The default-browser status is re-read once a minute and when the tray opens, so a router with no window notices another browser taking the default: the tray chip reads "not default" and the dropdown offers "Make default browser…".
- Local agents - Settings › Local agents offers Allow again and Forget on a revoked agent and Revoke asks before it acts; an approval window that closes unanswered is no longer a denial (the next call asks again); `pwrroute mcp` waits up to 20 s for PwrRoute to start; agents' writes to `rules.json` are serialized.
- App icon - The design's route mark on the Pwr family's dark tile is the app icon: PwrRoute.app, the DMG, the Windows Setup.exe, MSI and Start menu shortcut show it instead of the generic icon.
- Tray - Pause routing now pauses the router: every link goes to `rules.json`'s default browser (else the config's, else the fallback) after its rewrites, Activity and the dropdown's recents say which handler was skipped, and the pause row names the target as the files stand when the dropdown opens.
- Launch fallback - A browser a rule names that cannot be opened no longer loses the link: the router opens it in the fallback browser once, in a private window when one was asked for, and Activity shows what happened; the fallback is `rules.json`'s `defaultBrowser` and `defaultProfile` (first run's choice, read when a link falls back, so a new choice applies at once), then the OS's own browser.
- Native host - Finicky configs now see the real modifier keys, running apps, system and power info wherever a link is resolved (the router, Test a link, the Rules screen's test runs, `pwrroute rules test` and the MCP engine), and their `console` output is shown: a "Config output" row in Test a link, lines on stdout from `rules test`, and `console` in `pwrroute_resolve` and `pwrroute_rules_test` results.
- Short links - The router expands a link on a shortener's domain (bit.ly, t.co, aka.ms, Outlook safelinks and the rest of Finicky's list) to where it lands before the rules run, as Finicky did; Activity and `pwrroute_resolve` show both URLs, and Activity's Re-test, Save as test, Save as example and Add a rule use where the link landed (the window's Test a link does not expand yet). A config's `options.urlShorteners` now replaces the built-in list, and an empty list turns expansion off. Settings › Configuration lists the hosts the engine in charge expands.
- Tray and first run - Added the menu bar item (macOS) and notification-area icon (Windows, Linux) with Pause routing. On macOS a click opens a 300px dropdown with recent hosts; Windows and Linux use a native menu. On macOS the Dock icon now shows only while a PwrRoute window is open. Added the first-run window (`--first-run`), whose default-browser step asks the OS to make PwrRoute the default. The tray's recents come from the router's Activity.
- Router - Added the resident router: macOS Apple Events and Windows and Linux command lines reach one router per user, a second launch forwards its links over a local socket or named pipe, and each dispatch is resolved by the engine and kept with its trace in memory. The app declares `http` and `https`, and can register as a browser and ask to become the default on request. The router opens the browser and profile the rules pick through `pwrroute-browsers`.
- Installer and updates - Windows installs per user from a Velopack Setup.exe or MSI; macOS ships a DMG of the Velopack-packed app. Both check GitHub Releases at startup and from Check for Updates… (macOS menu), and download a newer release, which installs when PwrRoute quits or from Settings › Updates' Restart to update (see Resident lifecycle). Linux keeps the .deb and tar.gz.
- Browsers - Added `pwrroute-browsers`: a catalog of 33 browsers for macOS, Windows and Linux built on Finicky's `browsers.json`, installed-browser detection, Chromium and Firefox profile listing, and launch commands for the engine's result, with a dry run.
- Rust port - Replaced the Electron and pnpm scaffold with a Cargo workspace: a GPUI window that draws the Rules screen, a rules engine that runs Finicky v4 `.js` and `.ts` configs in QuickJS and is tested against Finicky, and `cargo xtask` tasks for lint, license notices and packaging on macOS, Windows and Linux.
- Scaffold - Added the workspace, CI, release pipeline, license checks, design mirror and a desktop stub that showed the PwrRoute title strip, since replaced by the Rust port.
