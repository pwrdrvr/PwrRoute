# Changelog

## Unreleased

- Rules - A `rules.json` rule or `defaultBrowser` that names a browser by bundle id or `.app` path now launches it when a profile is set (the handler carries Finicky's `appType`), macOS `open` starts a new instance whenever a config's `args` are passed so a running browser receives them, and a `~/` path expands to the home directory.
- Resident lifecycle - A downloaded update no longer applies at launch (a launch is usually for a link); it installs when PwrRoute quits, from the app menu or the tray, or from Restart to update. Checks run every 6 hours while running. The default-browser status is re-read once a minute and when the tray opens, so a router with no window notices another browser taking the default: the tray chip reads "not default" and the dropdown offers "Make default browser…".
- Local agents - Settings › Local agents offers Allow again and Forget on a revoked agent and Revoke asks before it acts; an approval window that closes unanswered is no longer a denial (the next call asks again); `pwrroute mcp` waits up to 20 s for PwrRoute to start; agents' writes to `rules.json` are serialized.
- App icon - The design's route mark on the Pwr family's dark tile is the app icon: PwrRoute.app, the DMG, the Windows Setup.exe, MSI and Start menu shortcut show it instead of the generic icon.
- Tray - Pause routing now pauses the router: every link goes to `rules.json`'s default browser (else the config's, else the fallback) after its rewrites, Activity and the dropdown's recents say which handler was skipped, and the pause row names the target as the files stand when the dropdown opens.
- Launch fallback - A browser a rule names that cannot be opened no longer loses the link: the router opens it in the fallback browser once and Activity shows what happened; the fallback is `rules.json`'s `defaultBrowser` and `defaultProfile` (first run's choice), then the OS's own browser.

- Launch fallback - A browser a rule names that cannot be opened no longer loses the link: the router opens it in the fallback browser once, in a private window when one was asked for, and Activity shows what happened; the fallback is `rules.json`'s `defaultBrowser` and `defaultProfile` (first run's choice, read when a link falls back, so a new choice applies at once), then the OS's own browser.
- Native host - Finicky configs now see the real modifier keys, running apps, system and power info wherever a link is resolved (the router, Test a link, the Rules screen's test runs, `pwrroute rules test` and the MCP engine), and their `console` output is shown: a "Config output" row in Test a link, lines on stdout from `rules test`, and `console` in `pwrroute_resolve` and `pwrroute_rules_test` results.
- Tray and first run - Added the menu bar item (macOS) and notification-area icon (Windows, Linux) with Pause routing. On macOS a click opens a 300px dropdown with recent hosts; Windows and Linux use a native menu. On macOS the Dock icon now shows only while a PwrRoute window is open. Added the first-run window (`--first-run`), whose default-browser step calls a hook and registers nothing. Tray and first run draw fixture data until the router and importer feed them.
- Router - Added the resident router: macOS Apple Events and Windows and Linux command lines reach one router per user, a second launch forwards its links over a local socket or named pipe, and each dispatch is resolved by the engine and kept with its trace in memory. The app declares `http` and `https`, and can register as a browser and ask to become the default on request. Opening browsers waits for the launcher.
- Installer and updates - Windows installs per user from a Velopack Setup.exe or MSI; macOS ships a DMG of the Velopack-packed app. Both check GitHub Releases at startup and from Check for Updates… (macOS menu), download a newer release and apply it on the next launch. Linux keeps the .deb and tar.gz.
- Browsers - Added `pwrroute-browsers`: a catalog of 33 browsers for macOS, Windows and Linux built on Finicky's `browsers.json`, installed-browser detection, Chromium and Firefox profile listing, and launch commands for the engine's result, with a dry run.
- Rust port - Replaced the Electron and pnpm scaffold with a Cargo workspace: a GPUI window that draws the Rules screen, a rules engine that runs Finicky v4 `.js` and `.ts` configs in QuickJS and is tested against Finicky, and `cargo xtask` tasks for lint, license notices and packaging on macOS, Windows and Linux.
- Scaffold - Added the workspace, CI, release pipeline, license checks, design mirror and a desktop stub that shows the PwrRoute title strip. No app code yet.
