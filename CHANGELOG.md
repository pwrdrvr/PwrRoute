# Changelog

## Unreleased

## v0.6.0 - 2026-10-28

- Send links - Temporarily send the next link, the next 1–99 links, or all links to a chosen browser, profile or private window. The macOS tray's Send links controls offer a countdown and an optional one-hour limit; Windows and Linux have Next link and All links in the tray menu. Overview shows the destination, offers Next link here on its nodes and Back to rules, and dims the rules while All links is active. Activity and traces label sent links and name the rule they skipped. Rewrites still run, private-window links are kept at most host-only, and quitting returns to Rules. Help and agent-opened links count toward Next link; Test a link does not. Send links and Pause routing replace one another.
- Browser and app pickers - Open in now shows one lane per browser in the rule editor and Activity's Add a rule sheet. Default, profiles and private windows are pills, so one click chooses the whole destination. Unknown browsers and profiles stay as written, with missing or unreadable choices identified, and Other app or profile by name keeps typed values available. Sent from shows app icons and names instead of typed bundle IDs; + app offers recent senders, apps named by existing rules and a way to choose an app in Applications.
- Activity quick rules - Hovering a full-link row shows + Rule without changing the row's layout; Everything else shows it even before hover. The expanded row puts Add a rule first below a link capped at two lines. Command-N, or Ctrl-N on Windows and Linux, opens the sheet for the open row menu or expanded row. The sheet can match Any link from the sending app, with Also catches restricted to that app. Long links fold to two lines with Show full link and a query-parameter count, keeping the match choices and buttons in view.
- Suggested patterns - Add a rule leaves queries and fragments out of every suggested pattern. A sign-in page with changing query values can therefore use the same rule on the next visit. Sign-in redirect and resource parameters no longer make the sheet incorrectly call the link a redirect wrapper or offer Add anyway. Long patterns end in an ellipsis with the full value in a tooltip, leaving room for their explanation.
- Rule menus and ordering - The Rules rows' ⋯ menus now move, duplicate, turn on or off, test and delete rules and rewrites. Drag rows within their list or use the keyboard to reorder them. Move choices show how many recent full links would change destination when at least 20 are available. Delete leaves an Undo row until the next edit, and Command-Z or Ctrl-Z restores it in place. Everything else's menu chooses the default browser and profile; a config's read-only rows offer its editor and importer. The importer's preview rows no longer show an inactive ⋯.
- Edge hand-off - On macOS, supported Edge channels again receive profile links directly over their singleton socket, using Edge's own message format instead of starting a second browser copy. A check against an isolated Edge instance verified that the selected profile received the URL. When the required uptime clock or socket hand-off is unavailable, Edge keeps its native launch fallback.
- Tray placement - On macOS 27 the tray dropdown opens beneath its item or the menu-bar click instead of in the screen's top-left corner. Positioning handles the status item's slight display overhang and the empty item window macOS reports for its overflow menu; keyboard activation keeps the item as its anchor when available.
- Build identity - The main window's rail and Settings › About identify the running build. Dev builds show the checkout, branch, commit and uncommitted-change marker, with individual Copy actions and Copy build info; clean tagged release builds show a compact version and commit without a checkout path in the rail. About adds source and build-time details, and Diagnostics includes the commit and the same copyable build report.
- Text clipping - One-line labels and inputs no longer cut off the bottoms of letters such as g, p and y. The correction covers Activity, Rules, Overview, menus, pickers, Settings and first run without expanding their rows.
- Overview ports - Browser cards no longer draw their border across the profile ports where routes connect. The dots and capsules remain visible over the card edge without moving the routes or nodes.
- Local-agent approval - Choose a role, then Allow as that role, instead of approving as soon as a role card is clicked. Reader is selected initially and the window lists the chosen role's permissions. Return allows and Esc denies; on macOS the panel opens without taking the keyboard, and other platforms ignore keys for the first 0.8 seconds. There is no five-minute expiry: the request stays while the agent is connected and closes shortly after its last waiting connection goes away, without recording a denial. After an answer, the result and permissions remain visible for six seconds, with a Local agents shortcut. Long client names wrap or truncate and the body scrolls rather than crowding the buttons.

## v0.5.0 - 2026-10-26

- Browser profiles - After a successful scan, PwrRoute remembers browser profile names, directory identifiers and default choices in its data folder. If macOS later blocks access to a browser's profile file, PwrRoute can still list and open the matching saved profiles; Settings labels them as cached and keeps the blocked-access status visible. A fresh readable file takes precedence, a missing file clears its saved profiles, and a malformed file does not replace the last good snapshot. The cache contains profile metadata, never the raw browser index or browsing history. It needs at least one successful scan with this version; profiles read by older versions were not saved.
- Start a rule from a link - Suggested patterns now use the URL after rewrites, which is the URL the rules match, while Try it keeps the original link and runs it through those rewrites. A rule started from a rewritten link therefore matches where the link actually went. Suggestion chips appear only while the rule is a draft, so they cannot overwrite a saved rule or another rule that takes its place in the list.
- Hand-off diagnostics - Help › Logs now shows browser hand-off stages at the normal logging level: planning, the delivery method and fallback reason, activation yield, and separate socket and command timings. The stages share a dispatch ID and attempt number, making retries and stalls easier to follow. Window observations report sampling delays and warn when PwrRoute stays in front through the timeout. Launcher completion is distinguished from a browser tab being ready, which PwrRoute does not observe. Progress lines contain labels, counts and timings, without link addresses, command arguments, browser or profile names, and follow the diagnostic-log and Activity-retention settings.

## v0.4.0 - 2026-10-26

- Profile access - First run on macOS now names browsers whose profile files macOS has blocked and shows how to turn on their access under Privacy & Security › Files & Folders › PwrRoute. Open Files & Folders goes to that pane; Check again and returning from System Settings read the profiles again, so the Everything else profile picker appears without a relaunch when access takes effect. Each browser shows its progress, Skip continues without profiles, and a grant that has not taken effect says that a quit and reopen may be needed. The step explains that PwrRoute reads a file to list profiles, never history, cookies or passwords; browsers that are missing or have no profiles do not trigger it.
- Default browser - On macOS, Set as default browser from first run, Settings or the tray now asks once per click, instead of opening two stacked consent dialogs on macOS 27. If an earlier answer made PwrRoute the handler for HTTP but not HTTPS, Ask again requests the remaining scheme. Setup still finishes only when both schemes use PwrRoute.
- Start a rule from a link - Add rule now starts with the last link PwrRoute opened: its narrowest suggested pattern is selected for editing, and Try it holds the link. Start from offers up to 20 distinct recent links, newest first, and Suggested chips offer wider patterns; Clear returns to a blank rule. Overview's first-rule prompt offers Add a rule for this link and Blank rule. The browser cards' + Rule and + Rule for a profile offer the picker without prefilling a pattern, so a draft is not saved before you choose one. Only full URLs held in Activity's memory are offered; with no links or host-only retention the picker says why it is unavailable. The link stays in Try it, and only the chosen pattern is saved once the rule has a browser.
- Edge hand-off - Links to a running Microsoft Edge now use its own launch method to pass the selected profile and URL, fixing links that could open a blank window in the wrong profile while Activity reported success. Chrome channels and Chromium keep the direct socket hand-off; Edge and other browsers whose protocol has not been verified use their own executable to construct the request. Those browsers may take longer to hand off a link.

## v0.3.0 - 2026-10-26

- Menus and Help - The menu bar now has File, Edit, View, Window and Help, with View opening Overview, Rules, Test a link and Activity. About PwrRoute opens Settings › About from the menu or tray. Help opens documentation, issue and security reporting, Replay Onboarding, Copy Diagnostics Info and Logs. Changelog, View License and Third-Party Notices open in their own windows, work offline and match the installed build; the Changelog marks its version as "This copy". Settings › About opens those same documents, and Diagnostics has Open Logs.
- Logs - Help › Logs follows the current and rotated diagnostic log, keeps the newest 5,000 lines and offers level filters, Live / Paused, line selection and Copy with optional diagnostics. Wrap is on by default; turning it off lets long lines scroll sideways. Search can Filter to matches with up to five lines of context on each side, or Highlight matches among all lines; hidden runs can be opened, and Enter / Shift-Enter step through matches. Mark and Select since mark collect the lines from a reproduction, with a selection ending on the newest line growing as new lines arrive. Wrap, search mode, context, Include diagnostics and Error / Warning / Info choices are remembered; the query and Debug choice are not saved.
- Windows and Linux menu bar - Every window's title strip now has File, Edit, View, Window and Help, making Logs and the other Help windows available there. Open menus with the pointer, a lone Alt, F10 or Alt plus a menu letter, then use the arrows and Enter; Edit acts on the field already in focus, and Window lists open windows. Windows gains a draggable title strip and minimize, maximize/restore and close buttons. Linux keeps its desktop's title bar and buttons. View's menu rows also work when the main window is already in front on macOS, and reopening a Help window from its own menu brings that window forward.
- Browser hand-off - On macOS, links to a running Chromium browser with a profile, private window or config arguments are sent directly to the browser when supported, avoiding a second browser process started just to pass the link along. If that hand-off is unavailable or fails, PwrRoute uses the previous launch method. On macOS 14 and later, PwrRoute yields the front so the browser can raise the window receiving the tab, rather than activating whichever window was last in front. Links meant for the background stay in the background. The diagnostic log records the hand-off method and times without the link's address or browser name.

## v0.2.2 - 2026-10-24

- Browser hand-off - On macOS 14 and later, a link to a Chromium browser with a profile (Chrome, Edge, Brave and the like) no longer leaves PwrRoute's window in front for up to two seconds while the browser waits its turn: PwrRoute gives the front to the running browser as it hands the link over. Measured on Chrome, every link came forward within about 220 ms, the first after a few idle minutes included. Links meant for the background, by the rule or by the config's `openInBackground` default, stay in the background.
- Agent approval - On macOS, the window that asks you to approve a local agent now opens over the terminal or editor the agent runs in, on the current Space, full screen included, and stays up until you answer, even if you switch to PwrRoute and back. Before, it could open behind that app where nobody saw it. Settings › Local agents says to start a new session in the agent after adding PwrRoute, and the diagnostic log notes each approval window it opens.

## v0.2.1 - 2026-10-24

- Rule editor - Every way to start a rule opens the same editor. The Rules screen has Add rule and Add rewrite under a Finicky config too, Overview's browser cards have "+ Rule" for the browser and "+ Rule for <profile>" for one profile, Test a link has "Add a rule…" with the narrowest pattern for the tested link, and Activity's sheet no longer preselects a browser. Open in and Profile are pickers built from the browsers and profiles on this Mac, with a field for anything else; a browser or profile this Mac doesn't have is kept, with a warning. Changing the browser clears a profile it lacks, and the private-window switch uses the browser's own word.
- Diagnostic log - PwrRoute writes `~/Library/Logs/PwrRoute/main.log` (`main.old.log` past 1 MB, readable by you only): its own messages, the updater's, and one line per link with where it came from, where it opened, the rule that chose it and how long each step took, including a short link whose shortener did not answer. On macOS a second line times the hand-off: whose window was on top when the link arrived, and when the browser's came to the front. Never a link's address; a `privacy: none` rule's links show times only, and nothing per link is written while Activity keeps nothing. Activity's retention note names the log.

## v0.2.0 - 2026-10-24

- App icons - On macOS, browsers and apps show their own icons, as Finder draws them, where they had a two-letter badge: the Overview's rules and destination cards, Rules, Activity, Test a link, Add a rule, first run, Settings › Browsers and Configuration, and the tray dropdown. Icons are read in the background and cached, and Settings › Browsers' Rescan reads them again. An app that is not installed keeps its letters, as do Windows and Linux for now.
- Overview routes and private windows - The Overview's spare width now goes to the routes between rules and destinations, where it went to an empty rule column. Browsers with a private mode end with a private-window node in their own word (Incognito, InPrivate, Private window): `rules.json` rules with `"private": true`, config handlers whose browser arguments open a private window and a private default route to it, and today's counts land on it only when a private window opened. A private rule to a browser with no private mode is tagged "not private". The precedence callout names both defaults by profile and window when they are the same browser.
- Release channel - Settings › Updates has a Release channel card: Stable or Beta, Latest or Prerelease. A copy follows the slot its version implies (a final release Stable · Latest, `-rc` Stable · Prerelease, `-beta` Beta · Latest, `-alpha` Beta · Prerelease) until you pick one, and the pick is saved in `settings.json`. Each slot updates to its highest release by version, read from the release list, so a final release no longer waits for a later one to be promoted. Automatic checks only move forward; Check now can download an older release for the picked slot, which installs only from Restart to switch.

## v0.1.0 - 2026-10-23

- Overview - The window now opens on Overview: whether links are routing (or paused, not reaching PwrRoute, or held up by a config that did not load or reload), a setup card for what is left, today's links, Everything else, rewrites and failures, and a map of every rule in the order it runs with a curve to the browser and profile it opens. Hovering a row or a card lights its routes, a click pins them, and rows open their rule in Rules. Rules opens as a list with nothing selected.
- Who takes everything else - With a Finicky config in charge, `rules.json` can say `"precedence": "pwrroute"`: its rules run before the config's handlers and its `defaultBrowser` takes every link nothing claims, in place of the config's (fixed, `null` or a function). Left out, the order is Finicky's as before. The Rules banner's switch, Overview's callout (with Undo), first run and Settings › Configuration › Everything else all write it, say what changes (a `defaultBrowser` function that stops running, a handler that matches every link, no default of PwrRoute's own) and, when the file cannot be written, leave the choice where the router has it and say why. `pwrroute_rules_apply` refuses a `precedence` other than `"pwrroute"` or `"config"`.
- Who routed a link - Activity, the tray's recents, Test a link, Try it and MCP traces name the rule that routed a link by its list and number ("rule 3" for `rules.json`, "config handler 2" for the config) and a default by its owner ("PwrRoute's default", "~/.finicky.ts's default"). Activity's Unrouted filter is now Everything else, and the Rules list counts today's links per rule.
- A config that does not load - When the Finicky config has never loaded (broken at launch, or broken when it first appears), PwrRoute leaves it out and routes with `rules.json` alone: your visual rules and rewrites keep running and PwrRoute's default takes everything else until the config loads, where before every link went to the fallback browser. A config that loaded once and then fails a reload still keeps routing with its last good version. Overview, the Rules banner, first run and Settings say which of the two it is.
- First run - With a Finicky config the steps are the config (keep it, import its rules or stop using it), Everything else (preselected from the config's default, the OS default or the first browser found, with who owns it while the config runs) and the default browser. Import N rules shows Importing… until the importer answers, Don't use it turns the config off, a choice that cannot be saved says why, and finished steps fold under Where links go.

## v0.1.0-rc.3 - 2026-10-22

- Window placement - New windows open on the display you are working on instead of the primary one: the main window from the tray (Open, Test a link, Rules, Activity), the Dock or the app menu, Settings, the importer, first run and an agent's approval window open on the display of PwrRoute's focused window, else the one under the pointer. A window that is already open stays where it is.
- Popovers and menus - The tray dropdown is as tall as what it shows, with no empty band below Quit, and grows or shrinks with it while open (keeping its top under the menu bar); on a display too short for it, the middle scrolls. Its pause line, tooltip and recents name a browser `rules.json` gives by bundle id ("Microsoft Edge", not `com.microsoft.edgemac`), as does Activity's Opened in. Select lists (Activity's Add a rule browser and profile, Test a link's app, first run's browser and profile, the agents' role) are at least as wide as their field and scroll past 8½ rows; a browser with three or more profiles shows a count instead of every name, and long names, profiles and the row menu's Save hint end in an ellipsis instead of running past the edge.
- Add a rule - With a Finicky config in charge, a rule added from Activity now shows on the Rules screen: the visual rules open with the new handler selected, and the row's menu offers Show handler N in Rules. Add checks the rule before writing it: a rule `rules.json` already has is not added again, and one that would never take its link (an earlier rule, or a config handler, takes it first, or the pattern misses) keeps the sheet open and says which; a second click adds it anyway.

## v0.1.0-rc.2 - 2026-10-22

- Browser hand-off - A profile, private-window or argument link for a Chromium browser that is already running opens without focus bouncing between apps. The short-lived instance `open -n` starts for the hand-off now starts in the background (`open -g`), and the running browser brings its own window forward. A browser that is not running still comes forward as before; Firefox is unchanged.
- App icon - On macOS 26 the app icon fills its squircle like other apps' instead of sitting shrunk on a light plate: the bundle ships an Icon Composer icon compiled into `Assets.car` (with a derived `Icon.icns` for older macOS) in place of a bare `.icns`.
- DMG - The macOS DMG opens to a window laid out like PwrSnap's, PwrAgnt's and PwrGit's: the PwrRoute wordmark, the app and an arrow to Applications on a branded background, the app icon as the volume icon, and a volume named `PwrRoute <version>-universal`.
- First run - Step 1 offers a profile for a browser that has them (Chrome, Firefox and the like) and saves it as `rules.json`'s `defaultProfile` beside `defaultBrowser`. Step 3 flips to done as soon as macOS reports PwrRoute as the default: the window re-reads the answer every second while it is open, and coming back to the window right after the dialog no longer counts as a refusal while LaunchServices catches up. A default browser PwrRoute's catalog does not list is named by its app ("PwrFinicky"), not its bundle id. The main window opens on the display the first-run window was on.
- Finicky importer - Import to visual rules…, first run's Import N rules, Settings › Configuration's Review import… and File › Import Finicky Config… open the importer: Review shows each rule's source lines and verdict (imports exactly, stays JS, or a suggested pattern the config's own function agreed with on every probe link), Place puts the imported handlers before, after or instead of yours, and Choose source keeps the config in charge or switches to visual rules (importing a file that is not in charge never puts it in charge or turns the one in charge off unasked); rules.json is written once, with Undo import, and the config is never changed.

## v0.1.0-rc.1 - 2026-10-21

- Rules - A `rules.json` rule or `defaultBrowser` that names a browser by bundle id or `.app` path now launches it when a profile is set (the handler carries Finicky's `appType`), macOS `open` starts a new instance whenever a config's `args` are passed so a running browser receives them, and a `~/` path expands to the home directory.
- Resident lifecycle - A downloaded update no longer applies at launch (a launch is usually for a link); it installs when PwrRoute quits, from the app menu or the tray, or from Restart to update. Checks run every 6 hours while running. The default-browser status is re-read once a minute and when the tray opens, so a router with no window notices another browser taking the default: the tray chip reads "not default" and the dropdown offers "Make default browser…".
- Local agents - Settings › Local agents offers Allow again and Forget on a revoked agent and Revoke asks before it acts; an approval window that closes unanswered is no longer a denial (the next call asks again); `pwrroute mcp` waits up to 20 s for PwrRoute to start; agents' writes to `rules.json` are serialized.
- App icon - The design's route mark on the Pwr family's dark tile is the app icon: PwrRoute.app, the DMG, the Windows Setup.exe, MSI and Start menu shortcut show it instead of the generic icon.
- Tray - Pause routing now pauses the router: every link goes to `rules.json`'s default browser (else the config's, else the fallback) after its rewrites, Activity and the dropdown's recents say which handler was skipped, and the pause row names the target as the files stand when the dropdown opens.
- Launch fallback - A browser a rule names that cannot be opened no longer loses the link: the router opens it in the fallback browser once, in a private window when one was asked for, and Activity shows what happened; the fallback is `rules.json`'s `defaultBrowser` and `defaultProfile` (first run's choice, read when a link falls back, so a new choice applies at once), then the OS's own browser.
- Native host - Finicky configs now see the real modifier keys, running apps, system and power info wherever a link is resolved (the router, Test a link, the Rules screen's test runs, `pwrroute rules test` and the MCP engine), and their `console` output is shown: a "Config output" row in Test a link, lines on stdout from `rules test`, and `console` in `pwrroute_resolve` and `pwrroute_rules_test` results.
- Short links - The router expands a link on a shortener's domain (bit.ly, t.co, aka.ms, Outlook safelinks and the rest of Finicky's list) to where it lands before the rules run, as Finicky did; Activity and `pwrroute_resolve` show both URLs, and Activity's Re-test, Save as test, Save as example and Add a rule use where the link landed (the window's Test a link does not expand yet). A config's `options.urlShorteners` now replaces the built-in list, and an empty list turns expansion off. Settings › Configuration lists the hosts the engine in charge expands.
- Tray and first run - Added the menu bar item (macOS) and notification-area icon (Windows, Linux) with Pause routing. On macOS a click opens a 300px dropdown with recent hosts; Windows and Linux use a native menu. On macOS the Dock icon now shows only while a PwrRoute window is open. Added the first-run window (`--first-run`), whose default-browser step asks the OS to make PwrRoute the default. The tray's recents come from the router's Activity.
- Router - Added the resident router: macOS Apple Events and Windows and Linux command lines reach one router per user, a second launch forwards its links over a local socket or named pipe, and each dispatch is resolved by the engine and kept with its trace in memory. The app declares `http` and `https`, and can register as a browser and ask to become the default on request. The router opens the browser and profile the rules pick through `pwrroute-browsers`.
- Installer and updates - Windows installs per user from a Velopack Setup.exe or MSI; macOS ships a DMG of the Velopack-packed app. Both check GitHub Releases at startup and from Check for Updates… (macOS menu), and download a newer release, which installs when PwrRoute quits or from Settings › Updates' Restart to update (see Resident lifecycle). Linux keeps the .deb and tar.gz.
- Browsers - Added `pwrroute-browsers`: a catalog of 33 browsers for macOS, Windows and Linux built on Finicky's `browsers.json`, installed-browser detection, Chromium and Firefox profile listing, and launch commands for the engine's result, with a dry run.
- Rust port - Replaced the Electron and pnpm scaffold with a Cargo workspace: a GPUI window that draws the Rules screen, a rules engine that runs Finicky v4 `.js` and `.ts` configs in QuickJS and is tested against Finicky, and `cargo xtask` tasks for lint, license notices and packaging on macOS, Windows and Linux.
- Scaffold - Added the workspace, CI, release pipeline, license checks, design mirror and a desktop stub that showed the PwrRoute title strip, since replaced by the Rust port.
